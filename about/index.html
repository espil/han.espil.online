Seven departments, one person

The AI Division of Labour

Seven departments is not a headcount. Each one is a craft I have practised for years - what changed is how the production underneath them is staffed. For Espil.Online I opened a set of specialized AI departments and run them the way a studio runs its floors: world and map production, 3D assets, character skills and motion, music, quality assurance, architecture, and a coordination office that keeps every department's state identical. Each works a defined scope, from a written brief, inside the documented laws.

Direction stays with one person. I set the canon, the priorities, and the order of work, and every consequential decision is mine - when the game's maps had to come first, every department was mobilized behind that single pipeline. The discipline is what makes the division professional rather than merely fast: decisions, blockers, and completions are broadcast to all departments in identical form, and nothing is called done until it has been verified against the live build and passed my own screen. Security and architecture are part of the same discipline: an architecture review stands before every production deploy, vulnerability review is a standing routine rather than a reaction to an incident, and code review is continuous and self-imposed - the floor a small or mid-sized company buys with a whole engineering team, run here by one person. Many hands, one judgment - that is the staffing the seven departments run on. The full account is in the Espil.Online case study.

CFull-Stack & Data

Backend runs through my whole career. At HMC (Han Mobility) I migrated an entire Excel customer list into a database with full CRUD, and built the company's intranet on the MERN stack. QDerm, a newly opened dermatology clinic, brought me in to build its website and consult on the network for its in-clinic devices; the CRUD booking system they asked for I built solo - React over a JSON API with a local database - and the clinic never put it into use. Ryde took the same work to APIs, integrating TransLink wholesale; today I build on Firebase and Vercel API processing, Espil.Online's own serverless endpoints included. Given a company's existing CRUD system, I can draw an API out of it and build on that - I have repeatedly moved channels off PHP backends onto APIs and worked through the problems that migration raises. I can read and extend PHP when a codebase needs it, but my own builds have always run on React, JSON APIs, and local databases.

DAI-Assisted Development

My headline workflow. I build with AI assistance — directing the tools, reviewing and editing the code myself, and choosing the right stack for each job. It is how Espil.Online ships, and how I built Plushy AI, my own local image-to-3D pipeline, run in Docker.

EOperations & Automation

Operations work taught me where hours actually go. At Discover Holidays I wrote Python tooling on the intranet API and macros that cut a months-long job to one day — accuracy first, then speed, in that order.
